### 2.4 Gaps found by this audit

**G1 — `STATUS.md` is stale by 28 commits.** *(defect)*

`D:\renderdoc_no_mcp\STATUS.md` declares itself 当前状态唯一事实源. Its baseline
is `ed59113` / 58 commits, scan date 2026-09-29. Actual is `a81600e` / 86
commits. It predates all 20 audited commits, including the entire execution
accounting, readiness, retirement and termination workstreams. Anyone consulting
it will be misinformed about the current state.

**G2 — `docs/CURRENT-EVIDENCE-FREEZE.md` is stale by ~29 commits.** *(defect)*

Same baseline (`ed59113` / 57 commits). It is the document the status table
points to as its own source.

**G3 — the full `tests/workload` suite has not been re-verified end-to-end**
*(verification gap)*

`discover -s tests/workload` was last run **before** the retirement and the
termination-evidence change. Per-module verification is current and green
(`test_workload_reliability`: 3 tests OK), but the aggregate was not re-run. The
suite is not a gate, so this does not affect the pipeline verdict — it means the
workload diagnostic is currently unverified as a whole.

**G4 — the capture corpus is not version-controlled.** *(structural evidence gap)*

0 tracked `.rdc`. 14 are present locally under `tests/workload/corpus/`. A clean
checkout has no captures, so `integration`, `cold_warm_equivalence` and the whole
workload suite are **not reproducible from the repository alone**. Readiness
reports `corpus.captures_present` honestly, and `.gitignore` covers the
directory, but the evidence depends on state outside version control.

**G5 — no gate has ever run on a hosted runner.** *(structural evidence gap)*

`git remote` is empty. `.github/workflows/ci.yml` is a declaration that has never
been executed. All gate evidence in this audit comes from local runs on one
machine. Cross-platform gate behaviour is therefore unverified — and this session
found a defect (`code < 0`) that would have been invisible on such a runner.

**G6 — `overall` can never currently reach PASS.** *(structural, by design)*

Two independent causes: Gate 4 is `PROCESS_ONLY`/`UNKNOWN` and by design keeps
the aggregate off PASS; and integration is `INFRASTRUCTURE_FAILURE`. Even a fully
green run of everything else yields `NEEDS_REVIEW` or `BLOCKED_INFRA`.

**G7 — the teardown defect makes release blocking unusable today.** *(dependency)*

If release blocking were enabled now, a required gate that passes 63 tests and
then cannot exit cleanly would block every change permanently. The scope decision
already recorded that fixing the teardown is a **precondition** for blocking, not
an improvement.
