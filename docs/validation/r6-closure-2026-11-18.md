## 2. 关键结论

- **真实负载不呈现合成瓶颈**：N3-05A1（60 资源/47 access/12 writer/5 reader）
  与 N3-05A2（36 资源/372 access/100 writer/245 reader）的 writer→reader
  边数均为 **0**，分析峰值内存 66KB–231KB，总耗时约 1.1–1.2s（主要来自
  replay 与资源枚举）。合成 512 行图的 33,024 条边不代表真实 capture。
- **远端阻塞是基础设施问题**：run `44316206734` 的 integration / cold-warm
  缺 env/module/capture，fork_integrity 缺外部 `../rdebug-validation` 元数据；
  无法在代码内闭合。远端 replay、cold-warm、fork 结果与部署状态保持
  NOT_ESTABLISHED，`BLOCKED_INFRA / exit 3` 仍是正确结果。
- **分项归因**：512 规模（tracemalloc 关闭）候选匹配 0.08ms、边生成 39ms、
  关系物化 68ms、解释 0.44ms（64 采样）、**整图序列化 519ms**、查询过滤
  22ms。另测得 tracemalloc 使图构建从 63.7ms 放大到 626.3ms，故 R5.1
  的 667ms 不是纯算法耗时（峰值内存数据仍有效）。
- **按需优化有效**：512 规模下全量构建+序列化+筛选 p50 660ms，下推流式
  12.5ms；两者返回相同 8,320 条边、关系集合一致。8/64/512 三档均一致。
- **语义未改写**：截断仍具名 `truncated` / `omittedEdgeCount`；筛选保留
  `partialBySelection` 与原状态；unknown 仍显式；stable ID 与旧 API 字段不变。
